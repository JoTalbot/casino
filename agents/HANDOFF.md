## 4. Ловушки, на которых я потерял время

**Тесты не ловят визуальные дефекты.** 21 зелёный тест и чистый `tsc`
при полностью развалившейся отрисовке барабанов. Правишь рендеринг —
снимай скриншот headless-браузером, иначе не узнаешь.

**Система координат символа в `pixi-reels`** — начало в левом верхнем
углу ячейки, не в центре. И **нельзя анимировать `view.scale`**: реел
читает трансформ `view`, чтобы понять слот символа. Масштабируй дочерний
контейнер.

**Канонический JSON для `configHash` — НЕ компактный.** Разделители
`", "` и `": "`, `sort_keys=True`, `ensure_ascii=False`. «Оптимизация»
до `(",", ":")` даёт другой хэш и ломает верификатор у всех уже
сыгранных раундов. Есть тест в CI.

**numpy-матрицы, размер которых зависит от параметра CLI, обязаны
считаться порциями.** Дважды получил OOM: `20000 x 10000 float64` —
это 1.6 ГБ. Прогон с `--quick` этого не показывает.

**`.git/config`, `node_modules`, `build/` и запущенные процессы не
переживают перерыв между сообщениями.** Симптом: `fatal: 'origin' does
not appear to be a git repository`. Лечение — в §7.

**Локально работает ≠ работает в CI.** Клиентские тесты читали `node:fs`,
а `@types/node` стоял только в корне: локально TS находил типы вверх по
дереву, `npm --prefix client ci` — нет. Проверяй фиксы воспроизведением
условий CI, а не «у меня же собралось».

Полный список — в `JOURNAL.md`, раздел ошибок каждой записи.

## 7. Восстановление окружения

`.git/config` не сохраняется между сессиями. Рецепт:

```bash
cd /path/to/casino
git config user.email "jo.talbot@gmail.com"
git config user.name "JoTalbot"
git remote add origin "https://<USER>:<TOKEN>@github.com/JoTalbot/casino.git"
git config branch.main.remote origin
git config branch.main.merge refs/heads/main
git fetch origin
```

Токен — у владельца. Дальше `npm install`, `npm --prefix client install`,
`pip install -r requirements.txt`.

Запуск прототипа:

```bash
npm run dev:server    # терминал 1, порт 3001
npm run dev:client    # терминал 2, порт 5173
```
