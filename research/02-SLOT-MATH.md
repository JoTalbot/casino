# 02 — Математика слотов: RTP, PAR sheets, волатильность

**Дата:** 2026-08-17 · **Агент:** claude-2026-08-17-A

> Математика определяет, будет ли игра зарабатывать, пройдёт ли сертификацию
> и захотят ли в неё играть.

---

## 1. Три числа, определяющие слот

| Метрика | Формула | Типичные значения |
|---|---|---|
| **RTP** | сумма выплат / сумма ставок | 94–97% онлайн; лучшие до 97.6% |
| **Hit Frequency** | спины с выигрышем / все спины | 20–35% |
| **Volatility** | разброс выплат | низкая / средняя / высокая |

House edge = `100% − RTP`. При RTP 96% казино удерживает 4% оборота на длинной дистанции.

Важно: RTP 96% **не значит**, что игрок вернёт 96 копеек с рубля за сессию.
Это предел на миллионах спинов. На коротких дистанциях разброс огромен,
и именно волатильность определяет ощущения игрока.

## 2. Reel strips — фундамент

Барабан — это не «5 случайных символов». Это **лента (strip)** с конкретным
списком символов на конкретных позициях. Случайность — это выбор точки остановки ленты.

Пример упрощённой ленты одного барабана (10 позиций):
```
[A, K, Q, J, 10, A, K, WILD, Q, SCATTER]
```

Если на ленте 10 позиций, а барабанов 3 — полный цикл = 10³ = **1000 комбинаций**.
Именно на «полном цикле» считается точный RTP.

### Символ появляется чаще → платит меньше

Базовое правило: высокооплачиваемые символы редки на ленте, дешёвые — часты.
Формально это управление весами. [LinkedIn / Betsson](https://www.linkedin.com/pulse/finding-out-math-rules-behind-slots-building-simple-slot-farrugia):
символы с высокой ценностью появляются реже, чтобы игра не переплачивала.

## 3. Виртуальные барабаны — патент Telnaes

Ключевая идея всей современной индустрии
([sudonex](https://www.sudonex.com/resources/slot-game-math-rtp/)):

Механический барабан имел ~22 физических стопа. 3 барабана = 22³ = 10 648 комбинаций.
Максимальный джекпот при этом ограничен: нельзя сделать выигрыш 1 к миллиону.

**Решение (патент Telnaes, 1984):** каждый физический стоп отображается
на несколько **виртуальных** позиций с разными весами.
Дешёвые символы получают много виртуальных позиций, джекпот-символ — одну.

Результат: игрок видит 22 символа на барабане, а вероятность джекпота — 1 к миллионам.
Это то, что делает возможными современные прогрессивные джекпоты.

**Для нас:** в коде это просто массив весов. `reel_weights[reel][symbol]`.

## 4. PAR sheet — главный документ

**PAR = Probability Accounting Report.** Полное математическое описание игры.
Подаётся в сертификационную лабораторию и является основным объектом проверки:
лаборатория сверяет, что реальный код соответствует PAR sheet **точно**
([sudonex](https://www.sudonex.com/resources/slot-game-math-rtp/)).

### Что содержит PAR sheet

1. **Reel strips** — полный список символов по позициям, физические и виртуальные
2. **Symbol distribution** — счётчики каждого символа на каждом барабане
3. **Веса символов** — механизм управления hit frequency
4. **Paytable** — каждая выигрышная комбинация и её выплата
5. **Ways to win** — подсчёт комбинаций для каждого правила выплат
6. **RTP breakdown** — вклад каждой фичи в общий RTP
7. **Bonus trigger probabilities** — вероятности запуска фич
8. **Wild/scatter rules** — все правила замен и краевые случаи

### Базовые допущения PAR sheet

([slotgamedesign.com](https://slotgamedesign.com/2019/01/19/slot-math-tutorial-creating-par-sheets/))
- Ставка = **1 кредит** за спин
- Расчёт ведётся для **одной линии** (даже в многолинейных играх)
- RTP и hit frequency считаются на **полном цикле**

## 5. Формулы

### Базовые

```
Total Ways   = произведение длин лент всех барабанов
Hit Frequency = Total Ways to Win / Total Ways
RTP          = Total Payout / Total Ways
Hit Rate     = 1 / Hit Frequency
```

### Классический пример: Liberty Bell

([slotgamedesign.com](https://slotgamedesign.com/category/slot-machines/))
```
Total Ways      = 1000
Ways to Win     = 264
Hit Frequency   = 264/1000 = 26.4%
Hit Rate        = 1/0.264  = 3.79  (выигрыш примерно раз в 4 спина)
Total Payout    = 756
RTP             = 756/1000 = 75.6%
```

### Эффект wild-символа

Тот же Liberty Bell с одним wild на одном барабане:
```
Hit Frequency: 26.4% → 27.4%
RTP:           75.6% → 88.0%   (+12.6 п.п. от ОДНОГО символа)
```

Вывод: wild — мощнейший рычаг RTP. Добавив wild, придётся снижать выплаты по линиям.

### Подсчёт хитов для комбинаций

([Elements of Slot Design](http://slotdesigner.com/wp/wp-content/uploads/Elements-of-Slot-Design-2nd-Edition.pdf))

Для точного совпадения на 3 барабанах:
```
hits(A,A,A) = count_A(reel1) × count_A(reel2) × count_A(reel3)
```

Для «любые 2 A» (третий — не A):
```
hits(any 2 A) = hits(A,A,#A) + hits(A,#A,A) + hits(#A,A,A)
где #A = (длина ленты − count_A)
```

RTP правила выплат:
```
RTP(правило) = (hits × prize) / (cycle × bet) × 100%
Общий RTP = сумма RTP всех правил
```

### Scatter-символы

Scatter платит из любой позиции в окне, не только на линии.
Если окно 3 символа в высоту, один scatter на ленте даёт **3 хита** вместо 1:
```
hits(S,S,S) = (3 × count_S₁) × (3 × count_S₂) × (3 × count_S₃)
```
При окне 4 символа — умножитель 4. Это надо учитывать явно.

### Приоритет выплат — частая ошибка

Если игра платит только лучшую комбинацию на линии, нельзя просто сложить все RTP.
Пример из Elements of Slot Design: без учёта приоритета RTP = 860%,
с учётом = 780%. Разница 80 п.п. — на такой ошибке игра проваливает сертификацию.

**Правило:** при подсчёте хитов для комбинации вычитай хиты, которые уже
засчитаны более приоритетной комбинацией.

### Free spins с ретриггером

([sudonex](https://www.sudonex.com/resources/slot-game-math-rtp/))
```
RTP = (B0 + p1 × n1 × B1) / bet

B0 — ожидаемый выигрыш базовой игры за спин
p1 — вероятность триггера фриспинов
n1 — ожидаемое число фриспинов за триггер
B1 — ожидаемый выигрыш за один фриспин
```

**С ретриггером** `n1` считается через бесконечный ряд:
```
n1 = начальное_количество / (1 − вероятность_ретриггера)
```

Забыть про ретриггер = занизить теоретический RTP = игра платит больше модели
= нарушение GLI-11 при полевом анализе. Это одна из самых частых ошибок.

## 6. Волатильность

Профессиональная шкала 0–10 учитывает как минимум:
- **Обратная hit frequency** (вес ~30%): реже платит → выше волатильность
- **Максимальный выигрыш** (вес ~20%): выше потолок → выше волатильность
- Плюс распределение выплат, вклад бонусной игры, дисперсия

| Профиль | Hit Freq | Макс. выигрыш | Ощущение |
|---|---|---|---|
| Низкая | 30–40% | 500–1000x | Частые мелкие выигрыши, долгая сессия |
| Средняя | 25–30% | 2000–5000x | Баланс |
| Высокая | 15–25% | 10000–50000x | Долгие простои, редкие крупные заносы |

Практическое замечание: одинаковый RTP при разной волатильности даёт
совершенно разные игры. RTP 96% low-vol и RTP 96% high-vol — разные продукты
для разной аудитории.

## 7. Расчёт RTP: точный vs симуляция

### Полный цикл (точный)

Перебор всех комбинаций. Даёт **точное** число.

Проблема масштаба: 5 барабанов по 256 виртуальных стопов = 256⁵ ≈ **1.1 триллиона**
комбинаций. Прямой перебор невозможен, нужна комбинаторная свёртка по символам,
а не по позициям.

### Monte Carlo (симуляция)

Стандарт индустрии. Требования лабораторий
([whimsygames](https://igaming.whimsygames.co/blog/slot-math-design-rtp-volatility-bonus-buy-and-megaways-mechanics-explained/)):

- Ни один прогон на 1 млн спинов не отклоняется от заявленного RTP более чем на **2%**
- Среднее по трём прогонам по 1 млн отклоняется не более чем на **0.5%**
- Частоты попадания конкретных комбинаций сверяются с PAR sheet

Практика: гонять **10+ млн спинов**, лучше 100 млн для стабильных цифр по редким фичам.

### Оптимизация под целевой RTP

Подогнать веса «на глаз» до ровных 96.00% практически невозможно.
Профессиональные инструменты используют Variable Neighborhood Search (VNS)
и генетические алгоритмы для многокритериальной оптимизации:
RTP + волатильность + hit frequency + max win одновременно.

Для нашего прототипа достаточно градиентного подбора весов скриптом.

## 8. Практический план построения математики

```
Шаг 1. Определить конфигурацию
       5 барабанов × 3 ряда, 20 фиксированных линий — классика, простая математика

Шаг 2. Список символов
       - 4 низких (10, J, Q, K или карточные масти)
       - 3-4 высоких (тематические)
       - WILD (НЕ на первом барабане — см. ниже)
       - SCATTER (триггер фриспинов)

Шаг 3. Составить черновые reel strips
       Длина ленты 30-50 символов на барабан

Шаг 4. Черновая таблица выплат
       Начать с типовых множителей, потом калибровать

Шаг 5. Симулятор Monte Carlo
       Считать: RTP, hit frequency, распределение выигрышей, частоту фич

Шаг 6. Итеративная калибровка
       Крутить веса, пока RTP не сойдётся к 96% ± 0.5%

Шаг 7. Зафиксировать PAR sheet
       Хэш конфигурации — в аудит-лог каждого раунда
```

### Где ставить wild

([slotgamedesign.com](https://slotgamedesign.com/category/math/))

- **Не ставь wild на первый барабан** — комбинаторика взрывается, PAR sheet
  и код оценки линий резко усложняются. Исключение: если wild сам является джекпот-символом.
- Wild сильно повышает hit frequency — это хороший рычаг для «ощущения» игры.
- Wild не должен заменять scatter — иначе фриспины триггерятся слишком часто.
- Если хочешь высокие джекпоты — не давай wild замещать джекпот-символ.

## 11. Референсный код: простейший симулятор

Из [LinkedIn / Betsson](https://www.linkedin.com/pulse/finding-out-math-rules-behind-slots-building-simple-slot-farrugia) —
минимальный пример 3-барабанного слота на весах:

```python
import random

symbols = [1, 2, 3, 4, 5]

# Веса по барабанам: чем больше вес, тем чаще символ
reel_weights = [
    [3, 2, 2, 1, 1],
    [2, 2, 2, 2, 1],
    [3, 1, 2, 2, 1],
]

def spin_reel(weights):
    return random.choices(symbols, k=1, weights=weights)[0]
```

Такая конфигурация даёт RTP ≈ 87.2%. Для реального продукта этого мало —
нужно 94–97%, что достигается калибровкой весов и таблицы выплат.

⚠️ В продакшене `random` заменяется на CSPRNG / provably fair генератор.
Для расчёта математики `random` допустим — там важна скорость, а не криптостойкость.
