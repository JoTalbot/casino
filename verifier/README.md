# Офлайн-верификатор раунда

Автономный HTML-файл, которым игрок может пересчитать любой свой раунд
и убедиться, что казино не подменило результат.

| Файл | Назначение |
|------|-----------|
| `verify.template.html` | Шаблон. **Правки вносить только сюда.** |
| `verify.html` | Собранный файл. Перезаписывается сборкой, руками не трогать. |

## Сборка и проверка

```bash
python3 scripts/build_verifier.py   # собрать verify.html
python3 scripts/test_verifier.py    # доказать, что он считает верно
```

Сборка падает, если фикстуры собраны на другой версии математики или если
в файле нашлось хоть одно обращение в сеть.

## Что делает верификатор

Игрок вводит серверный сид (раскрывается после ротации пары сидов), его
хэш (был опубликован до ставки), свой клиентский сид, номер раунда и
ставку. Файл:

1. считает SHA-256 от раскрытого серверного сида и сверяет с
   опубликованным хэшем — это не даёт подобрать сид задним числом;
2. пересчитывает позиции остановки барабанов из пары сидов и nonce;
3. разворачивает сетку по вшитым лентам и заново считает выплату,
   включая всю серию фриспинов с ретриггерами;
4. показывает каждый спин с подсвеченными выигрышными позициями.

Кнопка «Самопроверка» прогоняет 26 эталонных раундов, посчитанных
независимой реализацией на Python, — так игрок убеждается, что сам файл
не сломан.

## Три требования, которые нельзя нарушать

**Ноль внешних ресурсов.** Ни CDN, ни шрифтов, ни картинок, ни `fetch`.
Верификатор, который ходит на наш сервер, не доказывает ничего: мы могли
бы вернуть любой ответ. Игрок должен сохранить файл, отключить интернет и
получить тот же результат. `build_verifier.py` проверяет это девятью
паттернами и отказывается собирать файл с внешней ссылкой.

**Ноль зависимостей от браузерного крипто.** SHA-256 и HMAC написаны в
файле вручную. Причина практическая: `crypto.subtle` недоступен на
`file://` в ряде браузеров, а открывать файл будут именно так.

**Конфигурация вшита целиком**, вместе с лентами барабанов, и её хэш
показан в шапке. Он обязан совпасть с `configHash` из истории раунда:
если математика была другой, совпадение стопов ничего не доказывает.

## Как это проверяется

`scripts/test_verifier.py` извлекает JavaScript из собранного HTML и
прогоняет его в Node против полных фикстур:

| Проверка | Что доказывает |
|----------|----------------|
| SHA-256 против `hashlib`, 5 векторов | Пустая строка и строка длиннее блока — дополнение по FIPS 180-4 корректно |
| Поток HMAC против `slotmath/round.py`, 4 nonce × 24 числа | Совпадение до 15-го знака, включая переход через границу 32-байтного блока |
| 26 раундов, 136 спинов | Стопы, сетки, детализация выплат и итог совпадают полностью |
| Статический разбор файла | Нет сети, нет `Math.random`, хэш конфигурации на месте |

Последний прогон: все четыре группы пройдены, размер файла 40.2 КБ.

## Чего верификатор не доказывает

Он не подтверждает, что показанный хэш был опубликован **до** ставки —
это игрок должен сохранить сам. И не подтверждает справедливость самой
математики: за это отвечают `docs/PAR-SHEET.md` и независимая
сертификация RNG.

## После изменения математики

Порядок обязателен, иначе верификатор начнёт врать:

```bash
python3 scripts/build_game.py       # пересобрать config/game.json
python3 scripts/gen_fixtures.py     # перегенерировать эталонные раунды
python3 scripts/build_verifier.py   # пересобрать verify.html
python3 scripts/test_verifier.py    # убедиться, что всё сходится
```

Старые версии `verify.html` нужно сохранять: игрок может проверять раунд,
сыгранный на прошлой математике, и ему нужен файл с тем же `configHash`.
